# The Orville -- government overrides
#
# STRATEGY (all verified in source, this is why the previous version of this
# file was wrong):
#
#   Set<T>::Get  (Set.h:31)      returns &data[name] -- std::map::operator[].
#                                Re-parsing `government "Republic"` mutates the
#                                EXISTING object; it does not replace it.
#   UniverseObjects.cpp:156      governments.Get(name)->Load(node)
#   Government.cpp:491,493,499   "display name" / "friendly hail" /
#                                "hostile hail" / "language" are plain
#                                assignments => a later file OVERWRITES them.
#   "attitude toward"            per-target-key assignment => overwrites that
#                                pair only.
#   shouldOverwrite = {"raid"}   (Government.cpp:161) -- the only field with
#                                replace semantics; everything else merges.
#
# Consequence: we MUST reuse the real stock keys. Inventing `government
# "Planetary Union"` (as the previous draft did, for 15 of 18 blocks) creates
# an orphan key that nothing in map systems, fleets, missions, news, or
# outfitters references -- it spawns nothing and changes nothing. That was
# "added onto", which is exactly what you rejected.
#
# Renaming the KEY would mean chasing 200+ references across the whole data
# tree. Renaming only the DISPLAY NAME gives the player the Orville name in
# every place it is ever shown -- the HailPanel header, map labels, and all
# combat messages route through Government::DisplayName() -- while every
# internal reference keeps resolving. Stock data already does this itself:
# `government "Republic (Friendly)"` carries `"display name" "Republic"`.
#
# Blocks below are deliberately MINIMAL. Merge is cumulative, so any key not
# listed inherits its stock value (swizzle, color, crew attack/defense,
# confusion, raid, reputation bounds, bribe, fine). Copying stock fields in
# would only guarantee drift as upstream changes them.
#
# Every "display name" and phrase name here maps to a phrase that actually
# exists in data/orville/hails.txt, or to a stock phrase being intentionally
# reused ("friendly disabled", "hostile disabled", "ship bribe rejection
# navy"). No dangling references.
#
# NOTE ON `confusion`: valid names are defined in data/confusions.txt --
# player, civilian, militia, military, elite, pirate, miner, basic automata,
# advanced automata, kor mereti, kor sestor, ka'het, aberrant, wild, pug,
# perfect. The previous draft used "religious", "bureaucratic", "zookeeper"
# and "logic", none of which exist. UniverseObjects.cpp:266 warns and the
# field is dropped, so those blocks silently lost their pilot-skill profile.
# Omitted here; stock values inherited instead.
#
# NOTE ON `language`: no `language "..."` definition block exists anywhere
# under data/, so language names are not independently enumerable from data.
# Left unset; inherits stock.
